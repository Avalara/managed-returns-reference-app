# Amazon Q Integration with Managed Returns Reference App

## Overview

This document outlines how Amazon Q is integrated with the Managed Returns Reference App project and the specific rules and guidelines for using Amazon Q within this codebase.

## Amazon Q Rules

### Legal Header Requirement

All JavaScript (and similar) source files that are modified or generated by Amazon Q must include the Avalara legal header at the top of the file. This header is automatically applied according to the rules defined in `.amazonq/rules/AddHeader.md`.

## Best Practices for Using Amazon Q with This Project

1. **Code Generation**: When generating code with Amazon Q, ensure it follows the project's React and Ant Design patterns.

2. **Component Structure**: Follow the existing component structure in the project, with separate files for components and proper exports.

3. **Styling**: Use the theme tokens defined in `themeConfig.js` rather than hardcoded values.

4. **PropTypes Requirement**: Every React component MUST include PropTypes validation for all props to ensure proper type checking and documentation.

5. **Testing**: Ensure generated code includes appropriate PropTypes validation.

6. **Formatting**: All code will be automatically formatted according to the project's ESLint and Prettier configuration.

## Common Tasks

- **Adding New Components**: Use existing components as templates and ensure they follow the project structure.
- **Modifying UI Elements**: Check the theme configuration before making style changes. Follow the Ant Design patterns used throughout the application.
- **GraphQL Integration**: Reference existing query patterns in the `src/graphql` directory.

## Project Structure

- `src/components/` - React components organized by feature
- `src/graphql/` - GraphQL queries and mutations
- `src/routes/` - Route definitions and page components
- `src/theme/` - Theme configuration for Ant Design

## Development Workflow

1. Make changes with Amazon Q assistance
2. Run `npm run lint` and `npm run format` to ensure code quality
3. Test changes with `npm run dev`
4. Commit changes following the project's git workflow

For more information on the project setup, refer to the README.md file.
